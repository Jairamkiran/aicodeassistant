# Milestone 10 — Performance

**Objective.** Remove the one repeated cost on the authorized request path, make
the two expensive user-facing operations measurable, and let the UI recover from
a failed stream.

## Scope decisions (L6 review)

- **Cache exactly one thing.** Profiling the request path by inspection, the
  org-membership lookup is the only query that runs on *every* authorized
  request and *rarely* changes. That is the whole caching scope. Caching search
  results or LLM answers was rejected: both are high-cardinality and would trade
  a large memory footprint for a low hit rate.
- **Caffeine (in-JVM), not Redis** (ADR-0017). The point is to remove work from
  the hot path; a Redis round trip replaces a fast local query with a network
  call. Redis stays where it belongs (rate limiting, which needs to be shared
  across instances). Consequence documented: a membership change is visible
  within the TTL on *other* instances — acceptable for authorization grants that
  loosen or tighten within seconds, and evicted immediately on the instance that
  made the change.
- **A dedicated `MembershipLookup` bean**, not `@Cacheable` on the existing
  service method. Spring's cache proxy does not intercept self-invocation, so
  annotating a method called from within the same class silently does nothing —
  a classic false-confidence bug. Extracting the cacheable read makes the proxy
  boundary real, and the test *proves* it.
- **Measure before optimizing further.** Timers were added to search and RAG so
  the next performance milestone has data instead of intuition. No further
  tuning was done in this milestone on purpose.
- **Deferred:** load testing and SLOs, query-plan tuning, HNSW parameter sweeps,
  response compression.

## Verifying the cache actually caches

`MembershipLookupCachingTest` runs a real Spring context with caching enabled and
a **counting fake repository**: two identical lookups must produce exactly one
repository call, and a membership change must make the next lookup miss. This is
the test that would have caught the self-invocation trap.

## Testing strategy

- **Executed, no Docker:** `MembershipLookupCachingTest` (hit, miss-after-evict,
  proxy boundary real); existing `iam` authorization tests unchanged and green
  (caching must be behaviour-preserving); `RagChatServiceTest` updated for the
  timer dependency; `ModularityTests.verify()`. Frontend build + lint green.
- **Not executed:** throughput/latency benchmarking under load — there is no
  load-test harness on this machine, and no performance *numbers* are claimed.
  What is claimed is that the repeated query is eliminated and the two hot paths
  are now instrumented.
