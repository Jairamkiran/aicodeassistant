# Milestone 7 — Repository Code Chat (RAG) — FLAGSHIP

**Objective.** The centrepiece: ask a natural-language question about an indexed
repository and get a grounded, streamed answer with **citations to real
file:line**, remembering the conversation. Ties together M5 retrieval + M6 chat.

## Scope decisions (L6 review)

- **Windowed memory, not summarization** (ADR-0013): last N turns verbatim; no
  extra LLM call. Simpler, deterministic, testable.
- **SSE via Spring MVC, not WebSocket**: one-shot streamed completion fits SSE;
  WebSocket is reserved for M12 server-push.
- **Citations derived from retrieval, not parsed from model text** (ADR-0014):
  trustworthy provenance.
- **Prompt-injection guardrail**: retrieved repo content fenced as untrusted data.
- **Deferred:** cross-encoder re-ranking (M5 fusion suffices), rolling-summary
  memory, a DB-backed prompt registry (one code-defined template is enough).

## RAG flow

```
POST /api/v1/chat/sessions/{id}/messages  {question}
        │  (auth: own the session + read its org — iam OrganizationAccess)
        ▼
   RagChatService.askStream
     1. record USER turn (persisted immediately — durable even if generation fails)
     2. CodeSearch.search(question, org, repo)              ← M5 hybrid retrieval
     3. PromptAssembler:
          system(instructions + INJECTION GUARDRAIL + <context>[1..n] file:line</context>)
          + windowed prior turns (memory)
          + user question
          budget: pack chunks up to char budget, drop lowest-ranked
     4. ChatModel.chatStream(prompt)                        ← M6 streaming
        │
        ▼  SSE: event:token {delta} ... → event:citations [file:line] → event:done
     5. on stream completion: persist ASSISTANT turn (text + citations)
```

Citations are the chunks assembled into the prompt (id + file:line), so the UI
can link each answer to exact source lines — provenance from retrieval, not from
scraping the model's prose.

## Module design

- **`conversation`** owns sessions/turns (`chat_sessions`/`chat_turns`, Flyway
  `V10`; citations stored as a JSON TEXT column for Postgres/H2 portability) and
  the RAG orchestrator. It depends only on `retrieval :: search`, `ai :: chat`,
  and `iam :: api` — all public named interfaces, modularity-verified.
- **`PromptAssembler`** is pure (no I/O) → fully unit-tested.
- **SSE** via `SseEmitter`; the token stream is driven on a worker thread, tokens
  emitted as `token` events, then a `citations` event, then `done`; the assistant
  turn is persisted when the stream completes.

## API

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/chat/sessions` | Start a session (org read access) |
| GET | `/api/v1/chat/sessions?organizationId=` | List the caller's sessions |
| GET | `/api/v1/chat/sessions/{id}` | Session with its turns |
| POST | `/api/v1/chat/sessions/{id}/messages` | Ask; answer streams via SSE (token/citations/done) |

Authorization: caller must own the session (a foreign session returns 404, not
403 — no existence leak) and be able to read its organization.

## Testing strategy

- **Executed, no Docker (13 tests):**
  - `PromptAssemblerTest`: guardrail text present, `<context>` fencing, numbered
    `[n]` snippets with file:line, citations derived from included chunks, char
    budget drops lowest-ranked, windowed prior turns ordered before the question,
    empty-context handled.
  - `RagChatServiceTest` (fake search + chat + store): blocking answer with
    citations-from-retrieval, both turns persisted, search scoped to the session's
    org, **follow-up turn feeds prior turns as memory**, streaming assembles text
    and persists on completion.
  - `ChatControllerTest`: create-session authz (403), foreign session → 404, SSE
    `ask` produces an emitter that streams and invokes the persist callback.
- **Manual/live only:** end-to-end with real retrieval + a running LLM (needs
  Ollama/Docker) — the orchestration, prompt, memory, citations, guardrail, and
  streaming plumbing are all verified here with fakes.
