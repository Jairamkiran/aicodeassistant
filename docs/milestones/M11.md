# Milestone 11 — Platform Improvements

**Objective.** Close the lifecycle gaps a real tenant hits on day two: tell me
when indexing finished, let me re-index or delete a repository, let me rename or
delete a session, filter search by language, and clean up after failures. Also
reconcile the frontend with the API contracts it actually calls.

## Scope decisions (L6 review)

- **Notifications via a kernel signal, not a module dependency** (ADR-0018).
  `platform` gains a neutral `NotificationSignal`, mirroring the existing
  `AuditSignal` pattern. `repository` publishes a signal; it does not know the
  `notification` module exists. This keeps the dependency graph acyclic and lets
  notification delivery change without touching any producer.
- **A logging dispatcher behind a port, `@ConditionalOnMissingBean`**: the
  delivery seam is real and SMTP/Slack can be dropped in, but no email
  dependency ships until there is a reason. YAGNI with a documented seam.
- **Polling, not WebSocket push**: unread counts are cheap and low-frequency.
  A WebSocket would add connection lifecycle, auth handshake, and scaling
  concerns for a badge number.
- **Cascade deletes in the schema, not application code** (`V12`). Deleting a
  repository must remove its chunks and index job; enforcing that in Java means
  every future delete path has to remember. This also **fixed a latent bug** —
  before `V12` there was no FK from `code_chunks`/`index_jobs` to `repositories`,
  so a delete would have orphaned chunk rows and left them searchable.
- **Re-index reuses the existing saga**: `Repository.requestReindex()` moves a
  terminal repository back to `IMPORTING` and re-emits
  `RepositoryImportRequested`. The M4 saga is already idempotent, so re-indexing
  needed no new pipeline — only a guarded state transition.
- **Backwards-compatible `SearchQuery`**: the language filter added a 5-arg
  constructor while keeping the 4-arg one, so existing callers and tests stayed
  untouched.
- **The stalled-job reaper is the ADR-0009 follow-up**: the atomic status-claim
  chosen over a distributed lock has one consequence — a worker that dies
  mid-job leaves the row claimed. The reaper is that consequence's owner.

## Changes

| Area | Change |
| --- | --- |
| `platform` | `NotificationSignal` in the shared kernel |
| `notification` (was a stub) | Domain + JPA store (`V11`), REST list / unread-count / mark-read, `NotificationDispatcher` port + logging impl |
| `repository` | Re-index + delete endpoints; publishes `NotificationSignal` on index outcome; `RepositoryView` gains `statusDetail` / `updatedAt`; `V12` cascade FKs |
| `conversation` | Session rename (PATCH) + delete (DELETE) |
| `retrieval` | Optional language filter through `SearchQuery` → both DAOs → controller; `SearchRequest.limit` now optional |
| `iam` | `RefreshTokenMaintenance` — scheduled expired-token cleanup |
| `indexing` | `StalledJobReaper` — fails jobs claimed longer than the threshold |
| app / worker | `@EnableScheduling`; Grafana panels for search/RAG latency + token throughput |

## Frontend reconciliation

The M8 client had been written against anticipated contracts. This milestone made
it match reality: repositories are `owner`/`name`/`cloneUrl`; GitHub import uses
`GET /repositories/github` then imports by `owner`+`name`; search returns
`SearchHitView[]` with `snippet` (not `content`); sessions carry their turns
inline (no separate `/messages` GET); there is no `/progress` endpoint, so the
`useRepositoryProgress` hook was **deleted** in favour of polling repository
status directly. A `NotificationBell` with an unread badge was added to the shell.

Deleting the speculative hook rather than keeping it pointed at a nonexistent
endpoint is the M8 lesson: a client written ahead of its server accumulates
fiction.

## Testing strategy

- **Executed, no Docker:** notification service + signal-listener tests, store on
  H2; repository re-index guard (terminal-only) and delete authorization; session
  rename/delete authorization (foreign → 404); search language filter through
  both DAOs; `RefreshTokenMaintenance` and `StalledJobReaper` against fakes/H2;
  `ModularityTests.verify()` for the new `notification` boundary. Frontend
  build/test/lint green.
- **Authored, CI-verified:** `V11`/`V12` on real Postgres — in particular the
  cascade behaviour, which H2 approximates but Postgres is the authority for.
