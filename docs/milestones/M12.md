# Milestone 12 — Production Readiness

**Objective.** Make all three deployables shippable: static analysis in the
build, container images for every unit, Kubernetes manifests, hardened response
headers, and a production profile that does not leak operational detail.

## Scope decisions (L6 review)

- **PMD on main sources only, with a curated ruleset.** The default PMD rulesets
  are noisy enough that teams routinely disable the whole tool — a ruleset that
  cries wolf is worse than none. Kept: error-prone + selected best-practices.
  Excluded with reasons in the file: rules that fight records/DTOs, deliberately
  lazy streaming resources (`Stream.onClose`), and `instanceof`-in-catch used to
  re-throw domain errors. Style stays with Spotless/Checkstyle, which already own
  it. It found **two real bugs**: locale-less `toLowerCase()` in `Email` and
  `SearchQuery` — under a Turkish locale, `I` lowercases to `ı`, which would
  break email normalization and language matching.
- **nginx for the SPA, not a Java server.** The frontend is static files; serving
  them from Spring would couple release cycles and waste heap. The nginx config
  handles history fallback, proxies `/api`, and — critically — **disables
  proxy buffering on the chat stream**, because buffering would defeat SSE and
  make the flagship feature appear frozen.
- **Plain Kubernetes YAML, not Helm.** Three deployments with a shared configmap
  do not need a templating language; raw manifests are readable in a review and
  diff cleanly. Helm becomes worthwhile at multi-environment scale.
- **Security posture at the pod level**: non-root, dropped capabilities,
  read-only root filesystem, and all three probe types (liveness / readiness /
  startup) — startup probes matter because JVM boot plus Flyway migration is
  slower than a steady-state health check should tolerate.
- **Actuator locked down in prod**: `health`, `info`, `prometheus` only, with
  health *details* hidden. An open actuator surface is a reconnaissance gift.
- **Trace sampling reduced in prod**: full sampling is a dev affordance; keeping
  it would make Tempo the most expensive component in the stack.
- **Deferred:** Helm charts, registry publishing (an operator step, see
  `docs/DEPLOYMENT.md`), load testing, SLO alerting, external secret managers
  (`secret.example.yaml` is a template, never a committed secret).

## Deliverables

| Area | Deliverable |
| --- | --- |
| Static analysis | PMD in the java-library convention + `config/pmd/ruleset.xml`; part of `check` |
| Frontend image | `frontend/Dockerfile` (multi-stage Node → nginx, non-root) + `docker/frontend/nginx.conf` |
| Compose | `frontend` service under the `apps` profile |
| Kubernetes (`k8s/`) | namespace, configmap, secret template, `app` / `indexer-worker` / `frontend` Deployments + Services, HPAs, TLS ingress (SSE-friendly), README |
| Security headers | `SecurityHeadersFilter` in `platform-web` — nosniff, `DENY`, Referrer-Policy, `no-store` — on every response |
| Prod profile | `application-prod.yml`: actuator lockdown, hidden health details, `Secure` refresh cookie, graceful shutdown, forwarded headers, pool/thread tuning, reduced trace sampling, metric histograms |
| CI | Frontend job (install / lint / test / build) + frontend image build; PMD via `clean check` |

## Real findings fixed

`Email` and `SearchQuery` both called `toLowerCase()` without a `Locale`. Under a
Turkish default locale this changes `I` → `ı`, so the same email address could
normalize differently depending on the host's locale — a genuine correctness bug
in an authentication path, found by the tool added in this milestone.

## Testing strategy

- **Executed:** `./gradlew clean check` green **with PMD enabled** across all
  modules (the two findings fixed, not suppressed); frontend lint/test/build.
- **Validated by inspection/parsing:** all Kubernetes, compose, nginx, and
  `application-prod.yml` YAML.
- **Not executed on this machine:** actual image builds and a `kubectl apply` —
  there is no Docker daemon or cluster here. Image builds run in the CI
  `docker-build` job; the manifests are unapplied. This is stated rather than
  implied: **the deployment path is authored and reviewed, not smoke-tested.**
