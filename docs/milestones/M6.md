# Milestone 6 — AI Orchestration (Chat)

**Objective.** Provide a provider-agnostic **chat completion** capability — the
LLM half of RAG — behind one port with two real providers (Ollama default,
OpenAI), including token streaming. The chat-over-repository *feature* (RAG +
memory + UI) is M7; M6 delivers the tested capability.

## Scope decisions (L6 review)

This is the milestone where a **provider abstraction is finally warranted** (two
real implementations) — consistent with ADR-0006/ADR-0012. Deferred as
speculative-until-consumed: prompt template registry (→ M7), structured-output
parsing (→ M9), prompt-injection guardrails (→ M7), cost/billing ledger (→ M13;
M6 emits token **metrics** only), and a second embedding provider (no consumer).

## Design

```
                       ChatModel  (public 'chat' named interface)
                      /          \
   @ConditionalOnProperty       @ConditionalOnProperty
   provider=ollama (default)    provider=openai
        │                            │
   OllamaChatModel               OpenAiChatModel
   POST /api/chat                POST /v1/chat/completions (Bearer key)
   blocking: one JSON            blocking: choices[0].message + usage
   stream: NDJSON lines          stream: SSE 'data: {json}' + [DONE]
        \____________  both: JDK HttpClient (real InputStream for streaming),
                     \        Resilience4j retry+breaker, timeouts,
                      \       ai.chat.call + ai.chat.tokens metrics,
                       \      provider DTOs private, domain-typed I/O
```

- **Domain types** (`ChatMessage`, `ChatRequest`, `ChatResponse`, `ChatToken`,
  `TokenUsage`) are provider-neutral; JSON DTOs never leave the adapters.
- **Streaming in the port from day one:** `chatStream()` returns a closeable
  `Stream<ChatToken>` (holds the open HTTP response — callers use
  try-with-resources). M7 adapts this to browser SSE.
- **Failure model:** transient (timeout/429/5xx) → `ChatException.Unavailable`
  (retried, trips breaker); OpenAI 401/403 → `ChatException.CredentialRejected`
  (never retried). No provider exception leaks.
- **Provider selection:** `@ConditionalOnProperty` guarantees exactly one
  `ChatModel` bean; Ollama is `matchIfMissing=true` (offline default).

## Provider comparison

| Aspect | Ollama (default) | OpenAI |
| --- | --- | --- |
| Endpoint | `POST /api/chat` | `POST /v1/chat/completions` |
| Auth | none (local) | Bearer API key (secret) |
| Streaming | NDJSON (line per token) | SSE (`data:` + `[DONE]`) |
| Usage fields | `prompt_eval_count`/`eval_count` | `usage.prompt_tokens`/`completion_tokens` |
| Default model | `llama3.1` | `gpt-4o-mini` |
| Runs offline | yes | no (needs key + network) |

## Testing strategy

- **Executed, no Docker (12 tests):**
  - `OllamaChatModelTest` (WireMock): blocking content+usage, NDJSON streaming
    assembly (`Hel`+`lo`→`Hello`, done token carries usage), 5xx → exception.
  - `OpenAiChatModelTest` (WireMock): blocking content+usage, SSE streaming
    assembly + `[DONE]`, **401 → CredentialRejected** (non-retryable), 503 →
    Unavailable.
  - `ChatDomainTest`: request/message/token invariants.
  - App context loads with the Ollama `ChatModel` bean selected by default.
- **Manual/live only:** real Ollama or a real OpenAI key (logic fully verified
  via WireMock, so CI needs neither).
