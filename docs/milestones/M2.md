# Milestone 2 — Security Platform

**Objective.** Add the cross-cutting security features a real SaaS needs on top
of M1's authentication: **API keys** (programmatic access), **distributed rate
limiting** (abuse protection), and an **append-only audit log** (security
forensics).

## Scope decision (L6 review)

The roadmap originally listed five items. Two — **distributed locking** and
**Resilience4j wrappers** — had no consumer at M2 and were deferred to where they
are actually needed (M4 and M3 respectively). Building them now would have been
speculative infrastructure with zero callers. See
[ADR-0006](../adr/0006-defer-locking-and-resilience4j.md). M2 therefore delivers
three fully-consumed features rather than five, two of them dead.

## Features

### 1. API keys (in `iam`)

Programmatic credentials owned by a user, format `aca_<prefix>.<secret>`:

- **prefix** — non-secret public identifier, indexed for O(1) auth lookup.
- **secret** — 256-bit `SecureRandom` value; only its **SHA-256 hash** is stored
  (BCrypt is unnecessary for a high-entropy random secret and would preclude
  hash lookup). The raw key is returned **once** at creation, never again.

Endpoints (owner-scoped): `POST /api/v1/api-keys`, `GET /api/v1/api-keys`
(metadata only), `DELETE /api/v1/api-keys/{id}`. An `X-API-Key` request header is
an alternative to the JWT bearer path, wired into the security filter chain
before JWT processing; scopes (`READ`/`WRITE`/`ADMIN`) become
`SCOPE_*` authorities.

### 2. Distributed rate limiting (in `platform-web`)

Token-bucket limiter backed by Redis. The check-refill-consume step is a single
**atomic Lua script** on the Redis server, so concurrent requests across all app
instances cannot race — **without any distributed lock**. Tiered limits:
higher for authenticated principals (keyed by user/API-key), stricter for
anonymous (keyed by client IP). Breaches return `429` with `Retry-After` + an
RFC-9457 body and emit an audit signal. The filter runs inside the Spring
Security chain (after authentication, so the principal is known and still bound).

**Fail-open:** if Redis is unreachable the limiter allows the request rather than
taking the API down — see [ADR-0005](../adr/0005-rate-limiter-fail-open.md). When
Redis isn't configured at all, a no-op limiter is wired so the app still boots.

### 3. Audit log (new `audit` module)

Append-only record of security-relevant events. Other modules publish a neutral
`AuditSignal` (defined in the shared kernel); the `audit` module's single
listener records them — so audit couples only to `platform`, never to another
context's internals (clean Modulith boundary, verified by the modularity test).

Recorded in M2: `USER_REGISTERED`, `USER_LOGIN` (success **and** failure),
`API_KEY_CREATED`, `API_KEY_REVOKED`, `RATE_LIMIT_EXCEEDED`. Each row carries
actor, target, outcome, correlation id, and timestamp. Writes run in a
`REQUIRES_NEW` transaction and never throw, so auditing a failed/rolled-back
operation still persists and a storage failure never breaks the business call.

## Key design decisions & trade-offs

- **Neutral `AuditSignal` in `platform`** instead of audit depending on each
  module's event types, or each module calling an audit API directly. Simplest
  design that keeps the boundary clean: one publish, one listener.
- **SHA-256 for API-key + refresh-token secrets, BCrypt for passwords.** Random
  high-entropy secrets don't need a slow KDF and need deterministic hashing for
  lookup; user-chosen passwords need BCrypt's work factor. Right tool per input.
- **Rate limiter atomic via Lua, not locks.** A distributed lock around a counter
  would be slower and is unnecessary — Redis executes the script atomically.
- **Deferred locking + Resilience4j** (ADR-0006) — no consumers yet.

## Database schema

- `V3__api_keys.sql`: `api_keys` (prefix unique, secret hash, scopes, status,
  expiry, last-used; FK to users; partial unique index on active prefix).
- `V4__audit.sql`: `audit_events` (append-only; indexes on time, actor, type).

## Testing strategy

- **Domain unit tests:** `ApiKey` usability/expiry/revoke/scopes; scope CSV
  round-trip.
- **Rate-limit filter unit test:** in-memory limiter proves allow→deny→429 +
  `Retry-After` + problem body, and actuator exemption — no Redis needed.
- **iam H2 e2e (no Docker):** mint API key → authenticate with `X-API-Key` →
  list (no secret leaked) → revoke → rejected; malformed key → 401.
- **app H2 pipeline test (no Docker):** registration + failed login produce the
  expected `audit_events` rows via the cross-module signal path.
- **Testcontainers (CI):** `RedisRateLimiterIT` exercises the real Lua limiter on
  live Redis (capacity, denial, per-key isolation); `IamPersistenceIT` continues
  to validate JPA mappings on real Postgres.
