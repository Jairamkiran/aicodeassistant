# Milestone 13 — Finalization

**Objective.** Make the repository legible to someone who has never seen it:
complete documentation, a full ADR set, an accurate changelog and roadmap, and a
dependency list with nothing aspirational left in it.

## Scope decisions (L6 review)

- **Delete the dependencies we talked ourselves out of.** Three catalog entries
  described a system we deliberately did not build, and leaving them would
  suggest we shipped something we didn't:
  - `redisson` — superseded by the atomic DB status-claim (ADR-0009).
  - `spring-boot-starter-webflux` — the stack is servlet MVC; streaming uses
    `SseEmitter` and the JDK `HttpClient`.
  - `mapstruct` — all mapping is hand-written and small; the annotation
    processor never earned its keep.
  A stale comment in the java-library convention still referenced
  `libs.mapstruct`; removed with the entries.
- **Delete the OpenSearch compose service.** It had been dead since ADR-0011
  chose Postgres FTS for lexical search, and it was the single heaviest service
  in `docker-compose.yml` (a 512 MB-heap JVM plus a volume) for a component
  nothing connected to. Anyone running `docker compose up` was paying for it.
- **Re-enable two PMD exclusions.** `BeanMembersShouldSerialize` and
  `DataflowAnomalyAnalysis` were excluded defensively in M12; both are gone from
  PMD 7's error-prone category, so the excludes were dead configuration
  pretending to be a decision.
- **Four separate guides, not one giant README.** README answers "what is this
  and how do I run it"; deployment, configuration, developer setup, and API
  reference each have their own audience and lifecycle.
- **Honest status reporting over a clean scoreboard.** Every doc distinguishes
  what was executed from what requires Docker/a cluster/a live model. The
  roadmap's original M8–M15 plan was re-scoped to the delivered M8–M13; the
  table now reflects what exists, not what was once imagined.

## Final state

- **16 Gradle modules**, 2 deployables (`app`, `indexer-worker`) + 1 SPA.
- **10 implemented bounded contexts** (`iam`, `repository`, `indexing`,
  `retrieval`, `conversation`, `ai`, `codeintel`, `integration`, `notification`,
  `audit`) with Modulith-verified boundaries and explicit `allowedDependencies`;
  cross-module access only through named interfaces (`iam :: api`,
  `retrieval :: search`, `ai :: chat`, `integration :: github`).
- **2 modules remain declared-but-empty stubs**: `analytics` (usage/cost ledger)
  and `sdk` (public client library). They hold only a `package-info.java`. They
  are kept because the roadmap named them and the module skeleton documents
  intent — but nothing is implemented, and this doc says so rather than letting
  the module count imply otherwise.
- **18 ADRs** covering every architecturally significant decision.
- **Flyway V1–V12**; quality gates: Spotless, Checkstyle, PMD, Modulith
  modularity tests, plus frontend lint/type-check/tests.

## Known limitations (stated, not hidden)

- **No git remote is configured** — the entire history is local. Nothing has been
  pushed, and publishing requires the maintainer to add a remote.
- **No Docker on the development machine** — Testcontainers integration tests,
  image builds, and compose/Kubernetes runs happen in CI or on a Docker host
  only. Unit-level coverage is deliberately Docker-free.
- **Live LLM behaviour is manually verified.** Prompt assembly, parsing,
  citations, guardrails, and streaming are covered with fakes and WireMock;
  answer *quality* against a real model is not automatable here.
- **No load test or SLO alerting.** Latency metrics exist to support one.
