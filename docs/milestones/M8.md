# Milestone 8 — Web UI

**Objective.** Put a real product surface on the API: authenticate, import and
watch a repository index, search it, and hold a streaming, cited conversation
about it — in a browser.

## Scope decisions (L6 review)

- **React + TypeScript + Vite + MUI + TanStack Query + Monaco** (ADR-0016).
  Vite for fast builds, MUI so design effort goes into behaviour rather than a
  bespoke component library, TanStack Query because nearly all state here is
  *server* state (no Redux — there is almost no client state to manage), Monaco
  because we display code and citations must land on the exact line.
- **In-memory access token, never `localStorage`**: the refresh token already
  lives in an HttpOnly cookie (M1), so the access token is held in a module
  variable and re-minted by a silent refresh on load. An XSS cannot read a
  variable it does not have a handle on, and nothing survives a tab close.
- **Hand-written SSE parser, not `EventSource`** (`api/chatStream.ts`):
  `EventSource` cannot send an `Authorization` header and cannot POST, and the
  chat endpoint needs both. A `fetch` + `ReadableStream` reader over the same
  wire format is ~130 lines and keeps the auth model intact.
- **Citations re-query search rather than caching spans**: `CitationViewerDialog`
  fetches the cited chunk on open. Slightly more chatty, but there is one source
  of truth for file content and no stale-snippet class of bug.
- **Deferred:** WebSocket push (notifications poll in M11), offline/PWA support,
  i18n, a component-screenshot test suite.

## Structure

```
frontend/src/
  api/        client (RFC-9457 problem parsing), endpoints, types, chatStream, tokenStore
  auth/       AuthProvider (silent refresh), OrgProvider (org switcher)
  components/ AppLayout, ChatMessage, Citation*, CodeViewer, dialogs, feedback states
  hooks/      useChatStream
  pages/      Login, Repositories, RepositoryDetail, Search, Chat, CodeReview, Settings
  theme/      ColorModeProvider (light/dark), theme
```

## Features

| Area | Behaviour |
| --- | --- |
| Auth | Login/register, silent refresh on load, protected routes, logout |
| Orgs | Org switcher in the shell; every scoped query keys off the active org |
| Repositories | Dashboard, import (GitHub picker or clone URL), detail view with live indexing status polling, re-index, delete |
| Search | Hybrid search with language filter; results open in Monaco |
| **Chat (flagship)** | SSE token-by-token streaming, session history, clickable `[n]` citations that open the cited span in Monaco |
| Code Review | Severity-grouped structured findings (M9) |
| Settings | Profile, dark-mode toggle, API-key create/revoke |

## Cross-cutting concerns

- **Errors**: one API client parses RFC-9457 problem responses into typed errors;
  pages render a shared `FeedbackStates` (loading / empty / error) rather than
  each inventing its own.
- **Performance**: route-level code splitting via `React.lazy`, so the initial
  bundle carries the shell and login only; Monaco loads with the pages that need
  it.
- **Theming**: light/dark with the choice persisted; MUI `Grid2` throughout.

## Testing strategy

- **Executed:** Vitest + Testing Library — `problem.test.ts` (RFC-9457 parsing),
  `tokenStore.test.ts` (in-memory token lifecycle), `StatusChip.test.tsx`
  (status → colour/label mapping). Plus `tsc` type-check, ESLint, Prettier, and
  a production `vite build` in CI.
- **Manual:** the streaming chat and citation-to-Monaco flow against a running
  backend — the SSE parser and citation dialog are wired to real endpoints, and
  no automated browser harness is claimed here.
