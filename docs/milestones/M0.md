# Milestone 0 — Foundation & Platform Baseline

**Objective.** A running, observable, tested, containerized skeleton that boots
with `docker compose up` and proves every infrastructure dependency is wired —
before a single business feature exists.

## Delivered

### Build & modules
- Gradle (Kotlin DSL) multi-module build, **14 modules**, Java 21 toolchain.
- Self-contained Gradle **wrapper** (8.10.2) — no Gradle install required.
- **Convention plugins** in `buildSrc`: `aicodeassistant.java-library-conventions`,
  `aicodeassistant.spring-library-conventions`, `aicodeassistant.spring-boot-app-conventions`.
- **Version catalog** + Spring Boot 3.5 / Modulith 1.4 / Resilience4j BOMs.
- Spotless (google-java-format) + Checkstyle + `-Werror`, all enforced by `check`.
- Dedicated `integrationTest` source set excluded from the fast unit gate.

### Shared kernel (`platform`, servlet-free)
- RFC-9457 error model: `ErrorType`, `ApplicationException` + `ResourceNotFound`
  / `Conflict` / `Validation` subclasses.
- `DomainEvent` contract for outbox-externalized events (implemented by contexts
  from M3 onward).
- `PageResponse` / `PageRequestParams` (framework-neutral, bounded pagination).
- `Clock` auto-configuration and the `CorrelationId` MDC holder.

> Note: speculative helpers `BaseDomainEvent` and `Identifier<T>` were removed in
> the post-M0 production-readiness review (YAGNI — no consumers yet). They will
> be reintroduced with real usage if a context needs them.

### Web adapter kernel (`platform-web`)
- `GlobalExceptionHandler` (`@RestControllerAdvice`) rendering uniform problem
  details with `code` / `correlationId` / `timestamp`, sanitising 5xx.
- `CorrelationIdFilter` (highest precedence) + auto-configuration.

### Deployables
- `app` — `@Modulith` monolith aggregating all 11 contexts; actuator, OpenAPI,
  Modulith actuator/observability, JPA + Kafka + outbox (Modulith events-jpa /
  events-kafka), Ollama-default config.
- `indexer-worker` — headless deployable; actuator-only HTTP surface; depends on
  `platform` + `indexing` only (no `platform-web`).

### Persistence & events
- Flyway **V1 baseline**: `vector` + `pgcrypto` extensions, Modulith
  `event_publication` outbox table with partial index for incomplete events.

### Tests (green, no Docker)
- `ModularityTests` — `ApplicationModules.verify()` + architecture-doc generation.
- `ContextLoadsTest` — full app context boots with infra auto-config excluded.
- `WorkerContextLoadsTest` — worker context lean; business web layer absent.
- `platform` / `platform-web` unit tests (error model, correlation id,
  pagination, RFC-9457 rendering incl. secret-non-leak).
- **Total: 26 tests, 0 failures.**

### Integration harness (authored; runs where Docker exists)
- `IntegrationTestContainers` (singleton Postgres+pgvector & Kafka),
  `AbstractIntegrationTest`, `InfrastructureSmokeIT` (Flyway applied, pgvector
  present, outbox table exists, Kafka round-trip).

### Infrastructure & observability (authored; YAML/JSON validated)
- `docker-compose.yml`: Postgres/pgvector, Redis, Kafka (KRaft), OpenSearch,
  Ollama (+auto model pull), Prometheus, Grafana, Loki, Tempo; app/worker under
  an `apps` profile; healthchecks + named volumes.
- Multi-stage layered Dockerfiles (non-root, ZGC, actuator healthcheck) for both
  deployables.
- Prometheus scrape config, Grafana auto-provisioned datasources + "Service
  Overview" dashboard, Loki + Tempo configs, JSON logging with trace correlation.

### CI
- GitHub Actions: `build` (check), `integration-test` (Testcontainers on the
  Docker-equipped runner), `docker-build` (both images) with Gradle + buildx
  caching.

## Definition of Done — status

| DoD item | Status | How verified |
| --- | --- | --- |
| `./gradlew build`/`check` green incl. modularity | ✅ | Run locally: 26 tests pass, Spotless+Checkstyle pass |
| Spring Modulith boundary test passes | ✅ | `ModularityTests.verifiesModuleBoundaries` |
| Architecture docs generated | ✅ | `app/build/spring-modulith-docs/*.puml,*.adoc` |
| Testcontainers IT hits Postgres+Kafka | ⏳ authored | Runs via `./gradlew integrationTest` in CI / with Docker |
| `docker compose up` boots the stack | ⏳ authored | Runs on any machine with Docker; YAML validated |
| Grafana shows app metrics | ⏳ authored | Provisioned dashboard + scrape config; needs compose |
| CI passes on clean checkout | ✅ | Workflow authored; unit gate reproducible locally |

⏳ = authored and validated; execution requires a Docker daemon (absent on the
M0 authoring machine). No Docker-dependent result is claimed as "passed" until
it runs. See the README "Verifying M0" section.

## How to verify

```bash
./gradlew clean check          # unit gate (no Docker)
./gradlew integrationTest      # Testcontainers (needs Docker)
docker compose up -d           # infra + observability
docker compose --profile apps up -d --build   # + app & worker
```
