# Milestone 3 — Repository Context & GitHub Integration

**Objective.** Let users link GitHub and register (import) repositories into an
organization, emitting the event that will trigger indexing (M4). This is the
first **external provider integration**, built to the standing integration
directive.

## Scope decision (L6 review)

"Import" in M3 means **fetch repo metadata + persist as `REGISTERED` + emit
`RepositoryImportRequested`**. The actual clone → parse → chunk → embed → index
pipeline is the indexing worker + saga in **M4** — building it now would be
speculative. Webhooks (M11) and a second-VCS abstraction (no second provider
yet) are likewise out of scope. Resilience4j, deferred from M2, lands here around
the first real external calls (ADR-0006 → fulfilled).

## Architecture & module boundaries

```
repository  ──(github named interface)──▶  integration   ──▶ GitHub (HTTP)
     │                                          │
     └───────(iam :: api)──▶ iam            (encrypted token, internal)
```

- **`integration`** owns everything GitHub: OAuth flow, `RestClient`, JSON DTOs,
  Resilience4j, and the AES-GCM-encrypted token. It exposes only the `github`
  **named interface** (`GitHubGateway` + neutral `GitHubRepo`). Provider DTOs and
  the token live in `github.internal` and never cross the boundary — the token is
  resolved by `userId` inside the module.
- **`repository`** registers repos and requests import. It depends only on
  `integration :: github` and `iam :: api` (both declared as explicit
  `allowedDependencies`; verified by the modularity test).
- **`iam`** gained a public `api` named interface: `OrganizationAccess`, an
  intent-based ("tell, don't ask") authorization port (`canRead` /
  `canContribute` / `canAdminister`) so the `Role` enum never leaves iam.
- **`platform`** gained `EncryptionService` (AES-256-GCM) — a reusable kernel
  primitive for recoverable secrets.

## Sequence — link + import

```
Client         GitHubOAuthController   GitHubOAuthService   GitHubApiClient   Postgres
  │ GET /authorize     │                     │                    │             │
  ├───────────────────►│ (stash state)       │                    │             │
  │◄── authorizeUrl ────┤                     │                    │             │
  │  (user authorizes at GitHub, redirected back with code+state)  │             │
  │ GET /callback?code&state                                        │             │
  ├───────────────────►│ verify state ──────►│ exchangeCodeForToken│──HTTP──────►│(GitHub)
  │                    │                     │ fetchAuthenticatedUser──HTTP──────►│
  │                    │                     │ encrypt(token) ─────────────────► github_connections
  │◄── 204 ─────────────┤                     │                    │             │

Client        RepositoryController   RepositoryImportService   GitHubGateway   Postgres/Kafka
  │ POST /repositories/import                 │                    │             │
  ├────────────────────────────────►│ canContribute?(iam) ────────┤             │
  │                                  │ getRepository ─────────────►│(decrypt+HTTP)│
  │                                  │ save REGISTERED ────────────────────────► repositories
  │                                  │ publish RepositoryImportRequested ──────► outbox → Kafka
  │◄── 202 Accepted ──────────────────┤                            │             │
```

## Resilience & failure modes (integration directive)

Handled in the GitHub client + gateway; full table in
[ADR-0007](../adr/0007-github-integration.md). Summary: timeouts on every call;
`@Retry` (exp. backoff) + `@CircuitBreaker` on **transient** failures only
(429/5xx/timeout → `Unavailable`); 401 → `CredentialRejected` (no retry);
per-call Micrometer metrics (`github.api.call`) + WARN logs. Fails toward a clear
domain error, never a leaked provider exception.

## Security

- GitHub token encrypted at rest with **AES-256-GCM**
  ([ADR-0008](../adr/0008-aes-gcm-token-encryption.md)); never logged.
- OAuth callback validates an anti-CSRF `state` bound to the session.
- OAuth client id/secret + crypto key are secrets (env/secret; dev fallbacks
  clearly non-production).

## Database schema

- `V5__github_connections.sql`: one encrypted connection per user (FK to users).
- `V6__repositories.sql`: repositories with import status + `(org, provider,
  external_id)` uniqueness.

## API

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/v1/integrations/github/authorize` | Get GitHub authorize URL (stashes state) |
| GET | `/api/v1/integrations/github/callback` | OAuth callback → links account |
| GET | `/api/v1/repositories/github` | List the caller's linkable GitHub repos |
| POST | `/api/v1/repositories/import` | Import a repo into an org (member+) → 202 |
| GET | `/api/v1/repositories?organizationId=` | List imported repos (viewer+) |
| GET | `/api/v1/repositories/{id}` | Get one imported repo |

## Testing strategy

- **Unit:** AES-GCM round-trip + tamper/wrong-key detection; `Repository` state;
  `RepositoryImportRequested` event.
- **External integration via WireMock (executed, no Docker):** real HTTP round
  trips proving the failure matrix — success mapping, 401→CredentialRejected,
  429/503/timeout→Unavailable, OAuth success, OAuth error-body→CredentialRejected.
- **H2 e2e (executed, no Docker):** repository import persists `REGISTERED` +
  publishes `RepositoryImportRequested`; authorization gate; duplicate → 409.
- **Testcontainers (CI):** the existing Postgres persistence pattern validates
  the V5/V6 mappings.
